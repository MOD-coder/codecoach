# Prompt-gids: zo haal je het meeste uit CodeCoach


## De formule voor een goede vraag

CONTEXT (taal, niveau, opdracht) + DOEL (wat wil je bereiken) + MATERIAAL (code/foutmelding) + VORM (hint, uitleg, review, oefening).


## Voorbeelden

| In plaats van | Vraag liever |
|---|---|
| "Mijn code werkt niet" | "Python, beginner. Deze functie moet het gemiddelde berekenen maar geeft ZeroDivisionError bij een lege lijst. Hier is de code + foutmelding. Geef me een hint, niet de oplossing." |
| "Leg OOP uit" | "Leg encapsulatie uit voor een tweedejaars C#-student, met een analogie en een kort voorbeeld. Stel daarna één controlevraag." |
| "Maak deze opdracht" | "Dit is mijn opdracht. Help me het probleem te ontleden en geef pseudocode. Ik probeer het daarna zelf." |
| "Is mijn code goed?" | "Review deze Java-klasse op correctheid, leesbaarheid en randgevallen volgens de coderichtlijnen. Max. 5 punten." |
| "Oefening" | "Geef me 3 oefeningen over dictionaries in Python, oplopend in moeilijkheid, met een hint per opgave. Oplossingen pas als ik erom vraag." |


## Handige vervolgprompts

- "Leg het nog eens uit, maar simpeler / met een ander voorbeeld."
- "Waarom werkt mijn versie niet en de jouwe wel?"
- "Geef me alleen een hint voor de volgende stap."
- "Welke randgevallen mis ik?"
- "Maak hier een unit test voor."
- "Vat samen wat ik vandaag heb geleerd in 3 punten."
- "Wat zou een senior developer hier anders doen?"


## Wat je niet doet

- Toets- of examenopdrachten laten uitwerken.
- Persoonsgegevens, wachtwoorden of bedrijfsdata plakken.
- Antwoorden kopiëren zonder ze te begrijpen en te testen.


## Leer-modus tips

- Vraag om hints-eerst: je leert meer van zelf zoeken.
- Leg de code terug uit aan CodeCoach en vraag of het klopt (rubber duck).
- Vraag na een uitleg altijd om een mini-oefening.
- Houd een leerlogboek bij: wat leerde ik, waar liep ik vast?
